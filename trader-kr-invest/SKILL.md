# trader-kr-invest

장기 투자 실험실은 "이 방식으로 사서 들고 갔으면 시장을 그냥 들고 간 것보다 나았나" 를 묻는다. 비교 기준은
지수형 펀드에 가장 가까운 B1 (시가총액 상위 300 보통주를 시가총액 비중대로, 매달 맞춤)이다. 답은 비용을 뺀 뒤의
월 초과수익과 그것이 우연과 구별되는지(p 값)다. 16년 자료로도 연 2% 차이는 우연과 구별하기 어렵다. 그 답도 그대로
말한다.

`${CLAUDE_SKILL_DIR}` 는 이 SKILL.md 가 있는 폴더다. macOS·리눅스에서는 `python3`.

```bash
python "${CLAUDE_SKILL_DIR}/invest.py" data                     # 2010-01-04 부터 캐시에 없는 날만 (KRX 키)
python "${CLAUDE_SKILL_DIR}/invest.py" data --check             # 받지 않고 해마다 거래일·종목 수·사라진 종목 수
python "${CLAUDE_SKILL_DIR}/invest.py" rules                    # 규칙 이름 17개 (B1 + 16)
python "${CLAUDE_SKILL_DIR}/invest.py" run --rule "모멘텀12-1 30종목 매달" --from 2011-02 --to 2023-10
python "${CLAUDE_SKILL_DIR}/invest.py" run --rule "저변동성 50종목 분기" --delist B --cost-x 2 --json
python "${CLAUDE_SKILL_DIR}/invest.py" dca --months 36           # B1 을 한 번에 넣기 대 매달 나눠 넣기
```

## 읽고 쓰는 것

| 파일 | 내용 |
| --- | --- |
| KRX 일별매매정보 | 유가증권·코스닥, 2010-01-04 부터. 키와 두 서비스 이용신청이 필요하다 (README 의 KRX Open API 준비) |
| `trader-kr/cache/invest/days/YYYYMMDD.json.gz` | 그날 보통주 전부의 종가, 전일 대비, 시가총액, 거래대금. 처음 받을 때 약 8,800건 호출 |

처음 받는 데 키당 하루 한도(10,000건) 안에서 몇십 분 걸리고, 캐시는 200MB 쯤이다. 한도나 키 오류에 걸리면 그 자리에서
멈추고, 다음에 같은 명령을 부르면 이어 받는다. 평일이 7일 넘게 이어서 비면 한도 등으로 빈 답이 온 것으로 보고 그
날들을 지우고 멈춘다.

## 자료와 가정

- **수익률.** 하루 수익률 = 종가 / (종가 - 전일 대비) - 1. 전일 대비는 KRX 기준가와의 차이고, 기준가에는 분할·병합·
  감자·권리락이 조정되어 있다. 현금 배당은 빠진다 (가격 수익률). 첫 거래일 수익률은 쓰지 않는다 (공모가 기준).
- **종목군 U.** 신호일마다: 코드 끝자리 0 인 보통주, 이름에 스팩 없음, 그날 거래대금과 시가총액 > 0, 첫 거래일이
  12개월 전 월말 이전. 그 가운데 시가총액 상위 300.
- **신호와 체결.** 신호는 매달 마지막 거래일 종가까지의 자료, 체결은 다음 거래일 종가. 그 보유 수익률을 다음 달
  이름으로 적는다 (1월 말 신호 -> 2월 수익률). 보유 중에는 사 둔 그대로 두고 리밸런싱 달에만 맞춘다.
- **비용.** 매매한 비중에만: 수수료 0.015% (양쪽), 매도 거래세 0.20%, 밀림 0.10% (양쪽). 실제 매도세는 해마다
  0.15 ~ 0.30% 였다. `--cost-x 2` 로 두 배 판을 본다. 현금 이자는 0%.
- **상장폐지.** `--delist A` (기본): 보유 기간 끝에 행이 없으면 마지막 행 가격으로 판다 (합병, 정리매매 가격 반영).
  `--delist B`: 그 뒤로 다시는 행이 없으면 -100%. 거래정지 종목은 KRX 표에 거래대금 0 인 행으로 남아 다음 신호에서
  종목군에서 빠지고, 들고 있었으면 두 판 모두 멈춘 가격에 판 것으로 친다 (실제로는 팔 수 없어 낙관적이다).
- **코드 재사용.** 같은 코드가 1년 넘게 없다가 다시 나오면 다시 상장한 새 종목으로 친다 (앞 회사는 그때 사라진 것).
  2010 ~ 2026 자료에 2건 있었다 (인포피아 -> 오상헬스케어, 우양에이치씨).

## 규칙 16개

| 이름 | 고르는 법 |
| --- | --- |
| 동일가중 300 매달 | U 전부 같은 비중 |
| 모멘텀12-1 30·50종목 매달·분기 | 12개월 전 월말 ~ 1개월 전 월말 수익률 상위 |
| 저변동성 30·50종목 매달·분기 | 252 거래일 하루 수익률 표준편차 하위 (행 200개 이상) |
| 소형 30·50종목 분기 | U 안에서 시가총액 하위 |
| 52주고가근접 30·50종목 매달 | 신호일 가격 / 252 거래일 최고 가격이 큰 순 |
| 1개월반전 30종목 매달 | 지난 한 달 수익률 하위 |
| 추세타이밍 10·12개월 | 시장 지수가 최근 10·12개 월말 평균보다 위면 B1, 아니면 현금 |

규칙 안 종목은 같은 비중이다. 분기는 3·6·9·12월 말 신호일에만 바꾼다. 시장 지수는 이력 조건 없이 그날 거래된
보통주 전부를 시가총액 비중대로 묶은 가격 지수다.

## 결과 읽는 법

`run` 은 규칙과 B1 의 연복리·연 변동성·최대 낙폭, 월 초과수익 평균, Newey-West 표준오차 (lag 3), 0보다 크다는 한쪽
p, 달마다 바꾼 비중, 보유 중 사라진 종목 수를 낸다. 종목군이 300개보다 작은 달이 있으면 자료가 빠진 것으로 보고 멈춘다.

1. p 가 0.05 보다 크면 "기준보다 낫다고 말할 근거가 없다" 고 말한다. 연복리가 높아도 그렇다.
2. 16개를 다 돌려 가장 좋은 것을 고르면 우연이 섞인다. 여러 개를 봤으면 홀름 보정을 하고, 고르는 데 쓰지 않은
   뒤 기간에서 한 번 더 확인하라고 말한다.
3. 판 A 와 판 B 가 다르면 상장폐지 처리에 결과가 기대고 있다는 뜻이다. 둘 다 말한다.
4. 배당이 빠졌으니 배당을 많이 주는 종목에 몰린 규칙(저변동성 등)은 실제보다 낮게 나온다고 말한다.

## 절차

1. 처음이면 `data` 로 받는다. 몇십 분 걸리고 키 한도 안에서 이어 받는다고 말한다.
2. `data --check` 로 해마다 거래일(약 245일), 휴장 평일, 안 받은 평일, 한 시장만 빈 날을 본다. 빠진 날이 있으면
   결과를 내기 전에 다시 받는다.
3. 사용자가 묻는 규칙을 `run` 으로 돌리고, 판정 줄(초과수익, p)을 그대로 말한다. 기간을 정하지 않았으면 기본
   (2011-02 ~ 자료 끝)으로 돌리고 그렇게 말한다.
4. "지금 무엇을 사야 하나" 는 이 스킬이 답하지 않는다. 과거 성적만 말한다.

## 한계

- 가격 수익률이다. 배당이 빠져 모든 규칙과 B1 이 실제보다 낮고, 배당이 많은 쪽이 더 낮다.
- 16년, 약 190개월이다. 월 초과수익의 흩어짐이 크면 연 몇 % 의 차이도 0과 구별되지 않는다.
- 체결은 종가, 밀림은 고정 0.10% 다. 시가총액 하위 종목은 실제 체결 비용이 더 클 수 있다.
- 거래정지, 상장폐지 처리는 판 A 와 B 사이에 있다고 본다.
- 과거 성적은 미래를 약속하지 않는다.

- 교육과 도구일 뿐 투자 권유가 아닙니다 (not financial advice). 실험 결과는 과거 검증이지 추천이 아니고, 이 스킬은
  지금 살 종목 목록을 내지 않습니다.
- 주문은 trader-kr-broker 만 냅니다. 한국투자증권 모의투자 계좌로만 보내고, 이 팩의 어떤 스크립트도 토스증권
  주문 API(주문·정정·취소·조건주문)나 실전 계좌를 부르지 않습니다. 토스증권 계좌는 trader-kr-journal 이
  읽기만 합니다 (보유 주식, 주문 내역).
- 기본값은 보내지 않음 (`"send_orders": false`) 이고, 바꾸는 것은 사용자입니다. 주문은 세 가지가 모두 맞을 때만
  나갑니다: trader-kr-risk 가 오늘 그 주문 그대로 통과시켰고, 사용자가 채팅에서 그 주문 하나에 yes 라고 했고,
  Claude 의 도구 승인 카드에서 한 번만 허용을 눌렀을 때.
- 미수, 신용, 공매도는 쓰지 않습니다.
- KRX 키는 `~/.krx/api_key` 또는 환경변수 `KRX_API_KEY` 에 두고 채팅에 붙여 넣지 않습니다
  (`python krcommon/keys.py krx` 를 본인 터미널에서).
