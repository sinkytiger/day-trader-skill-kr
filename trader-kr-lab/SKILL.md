# trader-kr-lab

실험실은 "이 규칙이 비용을 내고도 남는가" 를 묻는다. 지난 자료에서 가장 좋았던 규칙을 고르는 것은 쉽다.
48개를 시험하면 그중 몇 개는 우연히 좋아 보인다. 그래서 고른 규칙을 고르는 데 쓰지 않은 뒤 기간에만 적용해
그 성적만 답으로 낸다. 그 답이 0과 구별되지 않거나 음수면, 그렇다고 말한다. 그것이 돈을 지키는 답이다.

`${CLAUDE_SKILL_DIR}` 는 이 SKILL.md 가 있는 폴더다. macOS·리눅스에서는 `python3`.

```bash
python "${CLAUDE_SKILL_DIR}/lab.py" run --symbols 005930,000660,035420       # 250 거래일
python "${CLAUDE_SKILL_DIR}/lab.py" run --top 10 --write                      # KRX 거래대금 상위 10 보통주
python "${CLAUDE_SKILL_DIR}/lab.py" run --symbols 005930 --train 60 --test 20 --slip-ticks 2
python "${CLAUDE_SKILL_DIR}/lab.py" run --top 10 --stop-pct 5                # 진입가 아래 5% 손절 규칙 32개를 더해 80가지
python "${CLAUDE_SKILL_DIR}/lab.py" run --symbols 005930 --json
python "${CLAUDE_SKILL_DIR}/lab.py" forward lock --rule "ORB30 저가손절 2R 거래량1.5x" --symbols 005930,000660 --name orb30
python "${CLAUDE_SKILL_DIR}/lab.py" forward update --name orb30                 # 장 마감 뒤, 매주
```

## 읽고 쓰는 것

| 파일 | 내용 |
| --- | --- |
| 토스증권 1분봉 | 종목마다 약 400일. 처음 받을 때 종목당 몇 분, 그다음은 `trader-kr/cache/` 에서 |
| KRX 일별매매정보 | `--top` 일 때만, 거래대금 순위 (KRX 키 필요) |
| `trader-kr/config.json` | 수수료, 매도세, 비용 필터 기준 (`max_cost_to_risk`, 기본 0.3) |
| `trader-kr/lab.json` | `--write` 때: 규칙별 표, 폴드별 선택, 시험 기간 성적, 비용 |
| `trader-kr/forward/<이름>.lock.json` | `forward lock`: 잠근 규칙, 종목, 비용, 잠근 날, 판정 건수, 체결 계산 지문. 고치지 않는다 |
| `trader-kr/forward/<이름>.json` | `forward update`: 종목별 거래일 수, 거래, 성적, 판정 |

## 규칙과 체결 가정

- **진입.** 09:15 ~ 14:50 에 끝난 5분봉 중 처음으로 시가 범위 고가 위에서 끝난 봉. 그 종가를 매수 호가로 올린 값.
- **손절.** 범위 중간값 또는 범위 저가를 호가 단위로 내림. 호가 2칸 또는 가격의 0.05% 보다 좁으면 거래하지 않음.
  `--stop-pct X` (또는 설정 `stop_rule` 이 `pct:X`) 면 진입가 아래 X% 손절 규칙 32개를 더한다: 범위 15·30분,
  목표 1·1.5·2R 과 목표 없음(손절 아니면 15:15 청산), 거래량 조건, 비용 필터. R 은 손절까지의 주당 위험이라,
  거래당 최대 손실로 수량을 정하면 손절 폭이 달라도 1R 은 같은 금액이다.
- **목표.** 진입가 + R x 위험, 호가 단위로 반올림. 지정가라 목표가에 체결된다고 친다.
- **청산.** 한 봉 안에서 손절을 먼저 본다. 봉 시가가 이미 손절가 아래면 그 시가에서(갭), 아니면 손절가에서
  `--slip-ticks` 칸 아래에서 체결. 둘 다 아니면 15:15 봉 종가에서 같은 칸만큼 아래.
- **거래량 조건.** 신호 봉 거래량이 범위 봉 평균의 1.5배 이상일 때만.
- **비용 필터.** 손절 때 비용(수수료 + 매도세)이 주당 위험의 30% 를 넘으면 건너뜀.

## 검증 방법

1. **전 기간 (참고).** 규칙마다 거래 수, 비용 전·후 평균 R, 승률, 평균 R > 0 의 한쪽 검정 p 값, 48개를 함께
   시험한 것을 보정한 홀름 p 값.
2. **워크포워드 (답).** 앞 `--train` 거래일에서 비용 뺀 평균 R 이 가장 큰 규칙(`--min-trades` 건 이상)을 고르고,
   뒤 `--test` 거래일에만 적용한다. 밀며 되풀이해 시험 기간 거래만 모은다. 그 평균 R 과 95% 부트스트랩 구간이
   답이다. 고를 때 평균 R 과 시험 기간 평균 R 의 차이가 고르는 데서 생긴 착시다.
3. **비용.** 비용 전·후 평균 R, 비용이 비용 전 이익에서 가져간 몫, 비용 필터를 켠 규칙과 끈 규칙 비교.

## 미래 검증 (forward)

워크포워드도 지난 자료다. 가장 깨끗한 검증은 규칙을 먼저 정해 두고 그 뒤에 생기는 거래일에만 적용하는 것이다.

1. **잠그기.** `forward lock` 이 규칙 하나(`run` 표의 이름 그대로), 종목, 비용(설정의 수수료·매도세, 밀림 칸,
   비용 필터 기준)을 잠근다. 잠근 날 뒤의 거래일만 대상이다 (장중에 잠가도 그날은 빠진다). 같은 이름이 있으면
   덮어쓰지 않는다. 다른 규칙은 새 `--name` 으로 잠근다.
2. **다시 재기.** `forward update` 는 새 1분봉을 받아 잠근 날 뒤의 온전한 거래일에 `run` 과 같은 체결 계산을
   적용한다. 잠근 파일이 바뀌었거나(지문), 규칙 정의나 체결 계산(`run_rule`)이 잠근 뒤 바뀌었으면 멈춘다. 자료를
   못 읽은 종목이 있거나, 다른 종목은 거래일이 있는데 거래일이 0일인 종목이 있으면 빠진 채로 성적을 내지 않고 멈춘다.
3. **판정 (잠글 때 정함).** 처음 `--judge-trades` 건(기본 200)의 비용 뺀 평균 R 95% 부트스트랩 구간 아래쪽이
   0보다 크면 "넘음", 아니면 "넘지 못함". 그 건수 전에는 "아직 (표본 부족)". 판정은 처음 200건으로 한 번만 한다.
   매주 들여다보다 좋을 때 멈추면 우연이 섞이기 때문이다. 그 뒤 거래는 참고로만 보인다.

20~30건으로는 아무것도 말할 수 없다. 거래대금 상위 10종목 250거래일 실험 한 번에서 시험 기간 거래 1건의 표준편차가
약 0.62R 이었다. 그 흩어짐이면 진짜 기대값 +0.1R 을 0과 구별하는 데 약 238건이 필요하고(한쪽 95%, 검정력 80%),
하루 0.8건이면 1년쯤 걸린다.
update 결과를 말할 때는 판정 줄을 그대로 말하고, "아직" 이면 몇 건 남았는지만 말한다.

## 절차

1. 종목을 정한다. 단타는 거래가 많은 종목에서 하니 `--top 10` 이 무난하다. 처음에는 종목당 몇 분 걸린다고 말한다.
2. `lab.py run` 을 돌리고 판정 줄을 그대로 말한다. 시험 기간 구간이 0을 포함하면 "남는다고 말할 근거가 없다" 고 말한다.
3. 전 기간 표의 상위 규칙을 "이게 돈 되는 규칙" 이라고 말하지 않는다. 고르기 전 성적이라 착시가 들어 있다.
4. 시험 기간에도 남는 규칙이 나와도, 한 번의 실험이라 기간과 종목을 바꿔 다시 확인하라고 말한다.

## 예시 (합성 자료)

합성 무작위 걸음 자료에서는 남는 규칙이 없어야 정상이고, 실제로 그렇게 나온다.

`python krcommon/demo.py` 의 8단계. 합성 종목 2개, 62 거래일, 학습 30일 -> 시험 10일:

```
2. 워크포워드 (앞 30 거래일에서 고르고 뒤 10 거래일에서 확인, 4번):
   2026-09-15~2026-09-28 고름: ORB15 중간손절 1R 비용필터           학습 -0.357 -> 시험 -1.416 (2건)
   2026-09-29~2026-10-12 고름: ORB15 중간손절 1.5R                  학습 -0.519 -> 시험 -0.851 (14건)
   2026-10-13~2026-10-26 고름: ORB15 저가손절 1R                    학습 -0.395 -> 시험 -0.310 (16건)
   2026-10-27~2026-10-28 고름: ORB15 저가손절 1R                    학습 -0.212 -> 시험 +0.261 (4건)
   고를 때 평균 R -0.371 이던 규칙들이 시험 기간에는 -0.518. 이 차이가 고르는 데서 생긴 착시입니다.

3. 비용: 전 거래 평균 R 비용 전 -0.323, 비용 뒤 -0.567, 비용이 비용 전 이익의 58% 를 가져감.
   비용 필터를 켠 규칙 -0.552 (831건) / 끈 규칙 -0.577 (1140건).

고른 규칙의 시험 기간 성적: 거래 36건, 비용 뺀 평균 R -0.518 (95% 구간 -0.883 ~ -0.137). 비용 뺀 기대값이
음수입니다. 이 규칙들로는 남는 게 없습니다. 전 기간 48개 규칙 중 비용 뺀 평균 R 이 양수인 것 0개, 홀름 보정 뒤 유의한 것 0개.
```

## 한계

- 5분봉으로 재생하므로 한 봉 안의 순서는 모른다. 손절을 먼저 본다 (보수적).
- 밀림은 고정 칸 수다. 실제 체결 비용은 호가창 두께에 따라 다르다 (`/trader-kr-budget` 이 그날 호가창으로 잰다).
- 거래정지, VI 단일가, 상·하한가 잔량은 봉에 보이는 만큼만 반영된다.
- 시험 기간 성적도 과거다. 미래를 약속하지 않는다.

## 안전

- 교육과 도구일 뿐 투자 권유가 아닙니다 (not financial advice). 실험 결과는 과거 검증이지 추천이 아닙니다.
- 주문은 trader-kr-broker 만 냅니다. 한국투자증권 모의투자 계좌로만 보내고, 이 팩의 어떤 스크립트도 토스증권
  주문 API(주문·정정·취소·조건주문)나 실전 계좌를 부르지 않습니다. 토스증권 계좌는 trader-kr-journal 이
  읽기만 합니다 (보유 주식, 주문 내역).
- 기본값은 보내지 않음 (`"send_orders": false`) 이고, 바꾸는 것은 사용자입니다. 주문은 세 가지가 모두 맞을 때만
  나갑니다: trader-kr-risk 가 오늘 그 주문 그대로 통과시켰고, 사용자가 채팅에서 그 주문 하나에 yes 라고 했고,
  Claude 의 도구 승인 카드에서 한 번만 허용을 눌렀을 때.
- 미수, 신용, 공매도는 쓰지 않습니다.
- 토스증권 client_id 와 client_secret 은 `~/.tossinvest/credentials.json` 또는 환경변수에 두고 채팅에 붙여 넣지 않습니다.
- 토스증권 자료는 본인 매매 목적으로만 씁니다. `trader-kr/cache/` 를 공유하거나 저장소에 올리지 않습니다.
