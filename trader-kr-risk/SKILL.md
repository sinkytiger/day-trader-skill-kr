# trader-kr-risk

위험 점검은 제안과 주문 사이의 문이다. BLOCK 은 그 주문에 대해 최종이다. 사용자에게 yes 를 묻지도
않고 다음 단계로 가지도 않는다. 단타를 하는 사람 대부분은 돈을 잃는다. 이 한도는 거래 하나와 하루의
손실을 작게 묶을 뿐, 거래를 이기게 하지 않는다.

`${CLAUDE_SKILL_DIR}` 는 이 SKILL.md 가 있는 폴더다. macOS·리눅스에서는 `python3`.

```bash
python "${CLAUDE_SKILL_DIR}/check.py"                            # trader-kr/ 파일들, 토스에서 종목 상태
python "${CLAUDE_SKILL_DIR}/check.py" --json
python "${CLAUDE_SKILL_DIR}/check.py" --no-write                 # 기록 없이 보기
python "${CLAUDE_SKILL_DIR}/check.py" --now "2026-10-28 10:15"   # 시계 고정 (한국 시간)
python "${CLAUDE_SKILL_DIR}/check.py" --no-network --status status.json
```

## 읽고 쓰는 것

| 파일 | 내용 |
| --- | --- |
| `trader-kr/orders.json` | 주문 제안 (trader-kr-budget) |
| `trader-kr/config.json` | 한도 (trader-kr-budget 의 `config.example.json`) |
| `trader-kr/portfolio.json` | 현금과 보유 종목. 없으면 예산만큼 현금이 있는 새 계좌로 본다 |
| `trader-kr/state/broker.json` | 오늘 낸 주문 기록: 중복, 거래 수, 하루 손실 (주문 단계가 생기면 씀) |
| 토스증권 종목 정보·매수 유의사항·상·하한가 | 주문 종목마다. `trader-kr/state/market_status.json` 에 남긴다 |
| 토스증권 현재가 | 15분 안의 가격이면 손실을 재는 데 쓰고, 손절가 이하면 막는다 |
| 토스증권 호가창 | 손절 때 밀림 추정. 보이는 매수 잔량보다 많이 팔아야 하면 경고 |
| 토스증권 장 운영 정보 | 오늘 휴장인지, 개장·접속매매 끝 시각. 못 받으면 막는다 |
| DART 공시 목록 | `DART_API_KEY` 가 있으면 그날 그 종목 공시를 경고 |
| `trader-kr/state/risk.json` | 판정과 주문마다 지문 |

## 진입과 청산

진입은 포지션을 열거나 늘린다 (매수). 청산은 가진 것을 줄이기만 한다. 빠져나가는 길은 늘 열려 있어야 하므로
청산은 형식과 공매도만 막고, 나머지 규칙(하루 한도, 시간, 손실, 손익비, 차단 목록, 금액, 중복)은 경고로 바꾼다.

## 점검 항목

주문은 파일 순서대로, 앞의 PASS 가 체결됐다고 치고 본다. 하나씩은 괜찮아도 합치면 한도를 넘는 묶음을 잡는다.

| 항목 | 막는 경우 |
| --- | --- |
| 형식 | 종목코드 6자리, buy/sell, 1주 단위 양의 정수, market/limit, day, 지정가·손절가·목표가는 호가 단위 |
| 공매도 | 가진 것보다 많이 파는 매도 (`allow_short` 는 끔) |
| 종목 | 주식이 아님 (ETF 는 `allow_etf`), 우선주 (`allow_preferred`), 상장 상태 ACTIVE 아님, KRX 거래정지, 정리매매 |
| 유의 | 오늘 걸린 투자경고, 투자위험, 단기과열, 정리매매, 신주인수권, 정적·동적 VI |
| 상태 모름 | 토스증권에서 종목 상태를 못 받음 (`require_market_status`: true, 기본) |
| 가격제한 | 진입가나 목표가가 상한가보다 높음. 손절가가 하한가보다 낮으면 경고 |
| 가격 | 15분 안의 현재가가 손절가 이하 (계획이 이미 깨짐). 시장가는 현재가가 계획 진입가보다 높으면 그 가격으로 손실을 잰다 |
| 계획 날짜 | 오늘 계획이 아님 |
| 손절 | 손절이 없음 (`require_stop`), 손절이 진입가 이상 |
| 손실 | 수량 x (진입가 - 손절가 + 손절 때 호가창 밀림) + 비용 이 `max_loss_per_trade_krw` 초과 |
| 비용 | 손절 때 비용과 예상 밀림이 주당 위험의 `max_cost_to_risk` (기본 30%) 초과 |
| 손익비 | 비용 뺀 손익비가 `min_reward_risk` 미만 |
| 하루 손실 | 오늘 진입들의 손절 때 손실 합 + 이번 것 이 `max_daily_loss_krw` 초과 |
| 거래 수 | 오늘 진입이 이미 `max_trades_per_day` |
| 시간 | 휴장, 접속매매 밖, `no_entries_before` 전, `no_entries_after` 뒤 (늦게 여는 날은 함께 옮김) |
| 금액·한도·현금 | `min_order_krw` 미만, `max_order_krw` 초과, `max_position_pct` 초과, 현금 버퍼 깸, 미수 |
| 중복·주문 수 | 같은 종목·방향이 묶음에 둘, 오늘 이미 냄, `max_orders_per_day` |

경고만 하는 것 (막지 않음): 신호 뒤 15분이 넘게 지남, 그날 그 종목 DART 공시 (`DART_API_KEY` 가 있을 때), 15분 안의
현재가가 없어 계획 진입가로 잼, 장 시간이 다른 날.

미국판의 패턴 데이트레이더 규칙은 국내에 없어서 뺐다.

## 절차

1. `/trader-kr-budget --write` 뒤에 `check.py` 를 돌린다.
2. PASS 면 진입가, 손절, 목표, 손절 때 손실, 비용 뺀 손익비를 말한다. 그래도 주문은 사용자가 그 주문에 yes 라고
   해야 하고, 1단계에는 주문 도구가 없다고 말한다.
3. BLOCK 이면 이유를 한 줄씩 그대로 말한다. 한도를 바꾸자고 먼저 권하지 않는다.
4. 경고(`~`)도 빠뜨리지 않는다. 특히 "평일 기본 장 시간" 경고는 휴장일 확인을 못 했다는 뜻이다.

## 예시 (합성 자료)

```
PASS  #1 매수 SYN001 합성종목 119주, 진입
          진입 30,450 (계획 진입가), 손절 30,100, 목표 31,150: 주당 위험 350원
          손절 때 손실 49,893원 (한도 50,000원), 비용 뺀 손익비 1.50 (최소 1)
```

같은 주문을 15:00 에 점검하면:

```
BLOCK #1 매수 SYN001 합성종목 119주, 진입
        - 시간: 14:50 뒤에는 새로 진입하지 않습니다 (지금 15:00)
```

## 하지 않는 것

주문을 내지 않는다. BLOCK 을 사용자 말 한마디로 PASS 로 바꾸지 않는다. 규칙을 바꾸려면 사용자가 자기 설정 파일을
고치고 다시 점검해야 한다. 종목 상태를 못 받았는데 괜찮다고 짐작하지 않는다.

## 안전

- 교육과 도구일 뿐 투자 권유가 아닙니다 (not financial advice). PASS 는 규칙 점검이지 추천이 아닙니다.
- 1단계에는 주문을 보내는 도구가 없습니다. 이 팩의 어떤 스크립트도 토스증권 주문·계좌 API 를 부르지 않습니다.
- 토스증권 Open API 에는 모의투자 서버가 없습니다. 나중에 주문 단계를 붙여도 기본값은 보내지 않음
  (`"send_orders": false`) 이고, 주문은 세 가지가 모두 맞을 때만 나갑니다: trader-kr-risk 가 오늘 그 주문
  그대로 통과시켰고, 사용자가 채팅에서 그 주문 하나에 yes 라고 했고, Claude 의 도구 승인 카드에서 한 번만
  허용을 눌렀을 때.
- 미수, 신용, 공매도는 쓰지 않습니다.
- 토스증권 client_id 와 client_secret 은 `~/.tossinvest/credentials.json` 또는 환경변수에 두고 채팅에 붙여 넣지 않습니다.
- 토스증권 자료는 본인 매매 목적으로만 씁니다. `trader-kr/cache/` 를 공유하거나 저장소에 올리지 않습니다.
