# trader-kr-today

여덟 스킬을 하나씩 부르는 대신 한마디로 하루의 다음 할 일을 본다. 스크립트가 지금 시각을 보고 필요한
스킬을 차례로 부르고, 후보마다 한 덩어리로 요약한다. 계산은 각 스킬의 스크립트가 그대로 하고, 이 스킬은
순서와 요약만 맡는다. 고르는 것은 사용자다.

`${CLAUDE_SKILL_DIR}` 는 이 SKILL.md 가 있는 폴더다. macOS·리눅스에서는 `python3`.

```bash
python "${CLAUDE_SKILL_DIR}/today.py"                          # 지금 시각에 맞춰
python "${CLAUDE_SKILL_DIR}/today.py" --max 5 --sim 0          # 후보 5개까지, 재생 안 함 (빠름)
python "${CLAUDE_SKILL_DIR}/today.py" --symbols 005930,000660  # 거래대금 상위 대신 이 종목만
python "${CLAUDE_SKILL_DIR}/today.py" --budget 5000000         # 설정 파일의 예산 대신
```

예산(`trader-kr/config.json` 의 `budget` 또는 `--budget`)이 없으면 손절·목표까지만 정하고 "계획만" 으로 보여 준다.
수량과 위험 점검에는 예산이 필요하다. 예산은 사용자가 정한다. Claude 가 임의로 정하지 않는다.

키 없이 흐름만 보려면 데모 폴더에서 저장된 파일로 돌린다 (`python krcommon/demo.py` 를 먼저 돌려 둔다):

```bash
cd trader-kr-demo
python "${CLAUDE_SKILL_DIR}/today.py" --offline bars --status status.json --now "2026-10-28 10:15:30"
```

## 시각별로 하는 일

| 시각 (기본 장) | 하는 일 |
| --- | --- |
| 09:00 전 | 장 전 일봉 스캔 (`/trader-kr-scanner daily`, KRX 키가 있으면 한국거래소 종가) |
| 09:00 ~ 09:15 | 시가 범위 형성 중. 새 진입을 보기 시작하는 시각과 첫 신호가 날 수 있는 시각 |
| 09:15 ~ 14:50 | 시가 범위 돌파 스캔 -> 후보마다 진입 확인 -> 청산 계획 -> 수량 -> 위험 점검 -> 통과 후보 재생 |
| 14:50 ~ 15:30 | 새 진입 없음. 열린 거래(일지)와 15:15 정리 시각 |
| 15:30 뒤 | 오늘 거래 일지 (`/trader-kr-journal report`, 토스증권에서 거래했으면 먼저 `sync`) |
| 휴장 | 휴장이라고 말하고 열린 거래만 |

늦게 여는 날은 토스증권 장 운영 정보로 시각을 옮긴다. 시각은 `trader-kr/config.json` 의 `no_entries_before`,
`no_entries_after`, `flat_by` 를 따른다.

## 읽고 쓰는 것

| 파일 | 내용 |
| --- | --- |
| 토스증권 Open API | 다른 스킬과 같음 (순위, 1분봉, 상·하한가, 호가창, 현재가, 매수 유의사항) |
| `trader-kr/today/<종목>/` | 후보마다 entry, plan, orders, risk, timemachine JSON |
| `trader-kr/today/report.md` | 단계마다 부른 명령과 전체 출력 |
| `trader-kr/today.json` | 이번 실행의 요약 (단계, 후보, 판정) |

## 절차

1. `today.py` 를 돌리고 출력의 카드를 그대로 보여 준다. 카드의 숫자를 고치거나 반올림해 바꾸지 않는다.
2. PASS 는 "규칙에 맞고 한도 안" 이라는 뜻이지 "사라" 는 뜻이 아니다. 재생 줄이 손절 쪽으로 기울면 그 말도 함께 한다.
3. BLOCK 과 주문 없음은 이유를 그대로 말한다. 한도를 바꾸자고 먼저 권하지 않는다.
4. 신호 뒤 15분이 지난 후보는 늦은 진입이라고 말한다.
5. 사용자가 샀다고 하면 가격, 시각, 수량을 묻고 그 후보의 계획으로 일지에 적는다:
   `python "${CLAUDE_SKILL_DIR}/../trader-kr-journal/journal.py" open --plan trader-kr/today/<종목>/plan.json --orders trader-kr/today/<종목>/orders.json --entry-price 가격 --entry-time HH:MM --qty 수량`
   토스증권 앱에서 샀다면 `python "${CLAUDE_SKILL_DIR}/../trader-kr-journal/journal.py" sync` 로 체결을 읽어 오면
   이 후보의 계획과 묶인다 (읽기만).
6. 한 후보를 더 자세히 보고 싶다고 하면 `trader-kr/today/report.md` 의 그 후보 부분을 보여 주거나 각 스킬을 따로 부른다.
7. 처음 재생하는 종목은 지난 60 거래일 1분봉을 받느라 종목당 1~3분 걸린다고 미리 말한다. 급하면 `--sim 0`.

## 예시 (합성 자료)

데모 폴더에서 `--now "2026-10-28 10:15:30" --replays 2000`:

```
오늘 장: 2026-10-28 (수) 10:15, 접속매매 중. 새 진입은 14:50 까지, 정리는 15:15.
스캔: 오프라인 3종목 중 3종목, 시가 범위 돌파 1종목.
신호가 가까운 1종목을 계획했습니다.

1. PASS      SYN001 합성종목  신호 10:15 (방금), 30,450
   손절 30,100 / 목표 31,150 (2R) / 15:15 까지 정리. 비용 뺀 손익비 1.50
   119주 = 3,623,550원. 손절 때 -49,893원, 목표 때 +74,788원 (비용 뺀 추정)
   호가: 시장가면 평균 30,500, 중간가보다 주당 25원 비쌈
   재생 2,000번: 목표 먼저 23%, 손절 먼저 60%. 닿은 것 중 목표 28% (본전 33%). 손절 쪽으로 기웁니다

통과 1, 막힘·주문 없음 0. 후보마다 따로 점검했습니다. 여러 개를 사면 하루 한도 (거래 3번, 하루 손실 150,000원) 를 함께 봐야 합니다.
```

## 한계

- 후보마다 따로 점검한다. 여러 후보를 함께 사면 하루 거래 수와 하루 손실 한도는 사용자가 합쳐 봐야 한다.
- 신호가 최근인 `--max` 개만 계획한다. 나머지 종목은 이름만 보여 준다.
- 재생과 위험 점검은 각 스킬의 한계를 그대로 가진다 (재생은 모의, 손절은 약속이 아님).

## 안전

- 교육과 도구일 뿐 투자 권유가 아닙니다 (not financial advice). 카드는 계산 결과이지 추천이 아닙니다.
- 주문은 trader-kr-broker 만 냅니다. 한국투자증권 모의투자 계좌로만 보내고, 이 팩의 어떤 스크립트도 토스증권
  주문 API(주문·정정·취소·조건주문)나 실전 계좌를 부르지 않습니다. 토스증권 계좌는 trader-kr-journal 이
  읽기만 합니다 (보유 주식, 주문 내역).
- 기본값은 보내지 않음 (`"send_orders": false`) 이고, 바꾸는 것은 사용자입니다. 주문은 세 가지가 모두 맞을 때만
  나갑니다: trader-kr-risk 가 오늘 그 주문 그대로 통과시켰고, 사용자가 채팅에서 그 주문 하나에 yes 라고 했고,
  Claude 의 도구 승인 카드에서 한 번만 허용을 눌렀을 때.
- 미수, 신용, 공매도는 쓰지 않습니다.
- 토스증권 client_id 와 client_secret 은 `~/.tossinvest/credentials.json` 또는 환경변수에 두고 채팅에 붙여 넣지 않습니다.
- 토스증권 자료는 본인 매매 목적으로만 씁니다. `trader-kr/cache/` 를 공유하거나 저장소에 올리지 않습니다.
