# trader-kr-journal

거래 일지는 계획과 실제 사이의 차이를 잰다. 단타에서 돈을 잃는 이유는 규칙이 나빠서만이 아니다. 신호 뒤
한참 지나서 들어가고, 손절가에 닿아도 버티고, 마감까지 들고 있는 습관이 같은 규칙을 더 나쁘게 만든다.
기록해 두면 그 습관이 숫자로 보인다. 체결 가격은 사용자가 알려 준 대로 적거나, 토스증권 계좌의 주문 내역을 읽어
적는다 (`sync`). 이 스킬은 주문을 내지 않는다.

`${CLAUDE_SKILL_DIR}` 는 이 SKILL.md 가 있는 폴더다. macOS·리눅스에서는 `python3`.

```bash
python "${CLAUDE_SKILL_DIR}/journal.py" open --entry-price 30450 --qty 119          # 지금 계획으로 진입 기록
python "${CLAUDE_SKILL_DIR}/journal.py" open --entry-price 30500 --entry-time 10:31  # 늦게 들어간 경우
python "${CLAUDE_SKILL_DIR}/journal.py" open --symbol 005930 --entry-price 72300 --qty 10 --stop 71700
python "${CLAUDE_SKILL_DIR}/journal.py" close last --exit-price 30100 --reason stop
python "${CLAUDE_SKILL_DIR}/journal.py" close 20261028-SYN001-1 --exit-price 31150 --exit-time 11:05 --reason target
python "${CLAUDE_SKILL_DIR}/journal.py" list --open
python "${CLAUDE_SKILL_DIR}/journal.py" report --since 2026-10-01
python "${CLAUDE_SKILL_DIR}/journal.py" sync --dry-run                  # 토스증권 오늘 체결 보기만
python "${CLAUDE_SKILL_DIR}/journal.py" sync                            # 토스증권 오늘 체결 적기
python "${CLAUDE_SKILL_DIR}/journal.py" sync --date 2026-10-30 --symbol 005930
python "${CLAUDE_SKILL_DIR}/journal.py" holdings                        # 보유 주식과 손절가까지 거리
```

## 읽고 쓰는 것

| 파일 | 내용 |
| --- | --- |
| `trader-kr/plan.json` | `open` 이 계획(신호 시각, 계획 진입가, 손절, 목표, 청산 시각, 셋업)을 같이 적는다 |
| `trader-kr/orders.json` | `--qty` 를 안 주면 주문 제안의 수량을 쓴다 |
| `trader-kr/config.json` | 수수료, 매도세, 거래당 최대 손실 |
| `trader-kr/journal.jsonl` | 거래 한 건에 한 줄. 저장소에 올리지 않는다 |
| `trader-kr/today/<종목>/plan.json` | `sync` 가 그날 그 종목 계획으로 묶는다 (`trader-kr/plan.json` 이 우선) |
| 토스증권 계좌 (읽기만) | `sync` 는 주문 내역, `holdings` 는 보유 주식. GET 만 보낸다 (`krcommon/tossacct.py`) |

## 재는 것

| 항목 | 계산 |
| --- | --- |
| R | (청산가 - 진입가) / 계획 위험 (계획 진입가 - 손절가). 비용 뺀 R 도 같이 |
| 손익 | 수량 x (청산가 - 진입가) - 수수료 - 매도 거래세 |
| 늦은 진입 | 실제 진입 시각 - 신호 시각. 15분이 넘으면 늦은 진입 |
| 진입 밀림 | 실제 진입가 - 계획 진입가 (호가 칸) |
| 손절 어김 | 손절가 아래에서 나왔는데 이유가 손절이 아니거나, 손절이라도 호가 2칸 넘게 아래. 손절가에서 나왔다면 덜 잃었을 돈도 센다 |
| 청산 어김 | 계획 청산 시각 뒤에 나왔거나 다음 날로 넘김 |
| 수량 초과 | 수량 x 계획 위험 + 비용 이 거래당 최대 손실을 넘음 |

## 토스증권에서 가져오기 (sync, holdings)

| 경우 | sync 가 하는 일 |
| --- | --- |
| 산 체결 | 새 기록. 그날 그 종목 계획이 있으면 묶고, 없으면 설정 `stop_rule` 이 `pct:X` 일 때 그 손절가 |
| 같은 날 또 산 체결 | 앞 기록에 평균가로 합침 |
| 손으로 먼저 적은 기록 | 수량이 같으면 토스 체결 값으로 맞추고 적어 둔 값을 남김 |
| 판 체결 | 열린 기록을 먼저 산 것부터 닫음. 일부만 팔면 판 만큼 떼어 닫음 |
| 일지에 없는 주식을 판 체결 | 적지 않고 알리기만 (전부터 갖고 있던 주식) |
| 아직 안 끝난 주문 | 체결 대기로 알리기만. 끝나면 다시 sync |

청산 이유는 가격으로 짐작한다: 손절가 이하면 손절, 목표가 이상이면 목표, 계획 청산 시각 뒤면 시간 청산, 나머지는
직접 청산. 손익은 토스증권이 준 실제 수수료·세금으로 잰다. 같은 주문 번호는 두 번 적지 않아서 여러 번 돌려도 된다.
모의투자 기록(메모가 "KIS 모의" 로 시작)은 건드리지 않는다.

`holdings` 는 국내 보유 주식마다 수량, 평균가, 현재가, 비용 뒤 손익, 손절가(일지, 없으면 설정 `pct:X` 로 평균가에서
계산해 `*` 표시), 손절가까지 남은 폭을 보이고, 일지에 있는 거래의 손절가 이하와 계획 청산 시각 지남, 일지와 수량이
다름, 일지에 없는 보유, 일지에는 열려 있는데 계좌에 없음을 "확인할 것" 으로 모은다. 일지에 없는 장기 보유 주식은 표에만
나오고 손절 경고를 하지 않는다. `--symbol` 로 종목을 고를 수 있다.

## 절차

1. 사용자가 샀다고 하면, 토스증권 키가 있으면 `sync --dry-run` 으로 체결을 보여 주고 맞다고 하면 `sync` 로 적는다.
   키가 없거나 다른 증권사면 가격, 시각, 수량을 묻고 `open` 으로 적는다. 계획이 있으면 계획과 묶인다.
   처음 쓰는 날은 `--dry-run` 으로 앱에서 낸 주문이 목록에 나오는지부터 확인한다.
2. 팔았다고 하면 `sync` 로 가져오거나 가격, 시각, 이유를 묻고 `close` 로 적는다. 손익과 R, 어긴 것을 그대로 말한다.
   sync 가 짐작한 청산 이유가 사용자의 말과 다르면 `close 번호 --exit-price 가격 --reason 이유 --force` 로 고친다.
3. "내 계좌 봐 줘" 나 장중 점검에는 `holdings` 를 돌리고 "확인할 것" 을 그대로 말한다. 손절가 이하라는 줄은 사용자가
   정해 둔 규칙을 다시 알려 주는 것이지 팔라는 권유가 아니다.
4. 주말이나 한 달에 한 번 `report` 를 돌려 습관을 말한다. 늦은 진입의 평균 R 이 제때 진입보다 나쁘면, 그것이
   가장 먼저 고칠 습관이라고 말한다.
5. 청산이 20건 미만이면 작은 표본이라고 말한다.

## 예시 (합성 자료)

계획은 10:15 신호, 진입 30,450, 손절 30,100, 청산 15:15. 실제로는 10:31 에 30,500 에 사서 15:20 에 30,000 에 팔았다.

```
기록했습니다: 20261028-SYN001-1  SYN001 119주, 진입 30,500 (10:31), 손절 30,100.
  주의: 늦은 진입 16분
청산했습니다: 20261028-SYN001-1  30,000 15:20 (직접 청산). 손익 -67,719원 (비용 8,219원 뺌), 비용 뺀 R -1.63.
  주의: 늦은 진입 16분
  주의: 손절 어김 (손절가 30,100 보다 100원 아래에서 나옴)
  주의: 청산 시각 15:15 를 넘김 (15:20 청산)
```

계획대로 손절가에서 나왔다면 손실은 위험 1R 에 비용을 더한 정도였다. 늦은 진입, 손절 미루기, 마감 넘기기가 겹쳐
-1.63R 이 됐다.

## 지킬 것

- 사용자가 말한 체결 가격을 고치지 않는다. 숫자가 이상하면 다시 묻는다.
- 어긴 것을 탓하지 않는다. 숫자로 보여 주고, 다음 거래의 계획을 지키는 쪽으로 말한다.
- 일지는 본인 기록이다. 공유하거나 저장소에 올리지 않는다.
- 토스증권 계좌는 읽기만 한다. 계좌번호는 끝 네 자리만 말하고, 보유 금액이나 계좌 내용을 다른 곳에 옮기지 않는다.
- 장기 보유 주식이 같은 계좌에 있으면 `--symbol` 로 단타 종목만 가져온다.

## 안전

- 교육과 도구일 뿐 투자 권유가 아닙니다 (not financial advice). 일지는 기록이지 추천이 아닙니다.
- 주문은 trader-kr-broker 만 냅니다. 한국투자증권 모의투자 계좌로만 보내고, 이 팩의 어떤 스크립트도 토스증권
  주문 API(주문·정정·취소·조건주문)나 실전 계좌를 부르지 않습니다. 토스증권 계좌는 trader-kr-journal 이
  읽기만 합니다 (보유 주식, 주문 내역).
- 기본값은 보내지 않음 (`"send_orders": false`) 이고, 바꾸는 것은 사용자입니다. 주문은 세 가지가 모두 맞을 때만
  나갑니다: trader-kr-risk 가 오늘 그 주문 그대로 통과시켰고, 사용자가 채팅에서 그 주문 하나에 yes 라고 했고,
  Claude 의 도구 승인 카드에서 한 번만 허용을 눌렀을 때.
- 미수, 신용, 공매도는 쓰지 않습니다.
- 토스증권 client_id 와 client_secret 은 `~/.tossinvest/credentials.json` 또는 환경변수에 두고 채팅에 붙여 넣지 않습니다.
- 토스증권 자료는 본인 매매 목적으로만 씁니다. `trader-kr/cache/` 를 공유하거나 저장소에 올리지 않습니다.
